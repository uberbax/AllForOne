# POLY Fantasy Female — аудит модульной геометрии

Источник: `D:/UnityProjects/AssetsView/Assets/Animpic Studio/POLY-FantasyCharacter/Meshes/POLY_FantasyFemale_Unity.fbx`.
Метод: отдельный headless Blender 5.1, чтение FBX, bounds, topology/UV/skin weights и contact sheets на текстуре T_Main_A. Исходный FBX, открытый Blender и Unity этим аудитом не изменены.

## Проверенные правила сборки

- Ровно 60 mesh objects. Имена source objects надо сохранять точно: торс A называется `CHR_Frmale_Torso_A` (опечатка в исходнике).
- Голова: `CHR_Female_Head` (шея и лицо включены); один вариант. Брови `SM_Female_Brows_A/B/C`; волосы `SM_Hair_D_01/E_01/F_01`.
- Торсы A–D — 4 коротких торса одежды. Плаща и длинной туники, зачёркнутых на пользовательском изображении, в этом женском FBX нет. Отдельных шлемов, ремней и наплечников нет; декоративные элементы встроены в выбранные meshes.
- Брюки `CHR_Female_Pant_{A/B/C/D}_01` длинные: нижняя граница 0.1124–0.1133 м. Варианты `_02` короткие: 0.3299–0.3358 м. Это варианты одной группы одежды, а не LOD.
- Обувь `SM_Boots_A/B/C/D` высокая (верх 0.3437–0.3549 м): включить короткие брюки `_02`. `SM_Boots_E/F` низкая (верх 0.1495/0.1268 м): длинные `_01`. Без обуви также нужны длинные брюки.
- `CHR_Legs` — пара голых стоп, НЕ ноги целиком; высота всего 0.0046–0.1160 м, bones Foot/ToeBase/Calf. Любая надетая обувь скрывает этот mesh полностью. Левая/правая обувь в каждом SM_Boots находятся в одном mesh.
- Для каждой стороны и каждого типа торса `CHR_Torso_{A/B/C/D}_Hand_{L/R}_01` — рука целиком от плеча, включая голую кисть и пальцы. `_02` — верхняя часть до локтя. `_03` — предплечье с голой кистью и пальцами. Полную `_01` нельзя включать одновременно с `_02` или `_03` на той же стороне.
- Без перчатки: либо `_01`, либо `_02 + _03`. Во всех этих случаях отдельный `CHR_Hand_L/R` должен быть выключен, иначе кисть дублируется. Все четыре верхние части и все четыре предплечья визуально стыкуются; у D_03 сначала удалить совпадающие дубли.
- Все `CHR_Glove_{A/B/C/D}_{L/R}` начинаются у локтя (abs X около 0.526 м) и занимают всё предплечье. С перчаткой включать верхнюю часть `_02 + Glove`, а `_01` и `_03` целиком выключать. Простое удаление кисти из полного рукава оставляет пересекающиеся предплечья.
- Перчатки A/C/D закрывают кисть и пальцы полностью. B — перчатка без пальцев с металлическим наручем. Ей требуется companion с открытыми пальцами; без него пальцы обрываются. Перчатка B сама замкнута топологически, поэтому отсутствие boundary edges не означает полное покрытие кисти.
- `Editor/GloveBFingerMask.json` содержит проверенную геометрию 26 сохраняемых полигонов на сторону (=52 треугольника, 36 уникальных позиций). Этот mask вырезает пальцы из CHR_Hand, убирает ладонь и запястье. Source positions в метрах Blender world. При генерации Unity triangles проверять, что все три позиции лежат в одном retained source polygon, с учётом conversion осей и масштаба. Индексы вершин после импорта Unity могут отличаться из-за UV/normal splits.

## Дефекты и важные тонкости source mesh

- `CHR_Torso_D_Hand_L_03` и `CHR_Torso_D_Hand_R_03` содержат по две точно совпадающие копии всего предплечья с кистью: 160 vertices и 148 polygons, из них 74 duplicate polygons. После удаления одной копии остаются 80 vertices/74 polygons до учёта дубликатов стыка. Обе копии кисти имеют UV, совпадающие со standalone CHR_Hand. В рендере дубликаты затемняют поверхность.
- Все 56 позиций standalone CHR_Hand совпадают со встроенной кистью в любой `_01`/`_03`. В A/B standalone hand topology совпадает с 52 polygons source arm; в C/D тоже 52 polygons, но эвристика «все вершины полигона входят в hand vertex set» дополнительно удаляет 2 полигона манжеты. Поэтому для отдельной bare-hand архитектуры использовать точное сопоставление полигонов/треугольников, не только набор вершин.
- В каждой D_03 встроенная кисть тоже продублирована: 104 matching hand polygons. Сначала дедупликация, затем extraction/culling.
- Все 60 meshes имеют Basis и V_None shape keys. V_None не отличается от Basis (максимальная разница <1e-6 source units); реального morph variation нет.
- Все source meshes используют один материал `T_Main_Pbr` и одну CC_Base skeleton систему. Полные bone weights и counts доступны в `mesh_inventory.json`. Перестановка meshes должна сохранять их bind poses, vertex attributes и mapping bones по именам.
- Рендеры проверяют исходную позу. Для production обязательно отдельно проверять изгибы локтя/кистей/колена в Unity Animator; общий локтевой срез не доказывает отсутствие щели при любой анимации.

## Дополнительная проверка алгоритмов генерации

Точный эмулятор `FemaleFingerMeshBuilder` на фактических source vertices сохраняет **52 треугольника на каждую кисть**. Проверка всех точек mask и подбор permutations/signs/scales работают для исходного FBX: Blender local → audit world согласуется с обратным scale 100.

Для D_03 уточнено: source содержит **296 треугольников на сторону**, после геометрической дедупликации должно остаться **148**. Ключ `position + UV + normal` удаляет только 136, потому что у шести quad-полигонов манжеты совпадает геометрия и нормали, но различается UV. Это source polygons 12–17 в первой копии и 86–91 во второй.

Правильный цвет манжеты имеет **вторая копия**: её UV `(0.054066, 0.271473)` выбирает в точности тот же цвет, что соответствующие polys 63–68 полной руки D_01, во всех шести текстурных палитрах. Первая копия UV `(0.017629, 0.273251)` использует другой светлый цвет. Следовательно, для этой пары дубликатов надо сохранить вариант с UV, наиболее близким к D_01, а не просто первый triangle occurrence. Для остальных дубликатов UV и normals совпадают.

Все 80 соответствующих пар вершин двух копий имеют одинаковые bone-name → weight mappings (различий >1e-7 нет), на обеих сторонах. Безопасный для данного источника результат: геометрический ключ позиции с сохранением winding; при UV conflict выбрать поверхность по эталону D_01; убедиться, что осталось 148 triangles. Нулевое количество удалений допустимо только если в импортированном mesh уже 148 triangles; само по себе `removed == 0` не подтверждает отсутствие дубликатов.
